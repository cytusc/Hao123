## 1. 目标与边界

### 1.1 目标

重新梳理首页首屏与目录视觉，使用户进入页面后能快速理解“在这里搜索、从这里访问常用网站”，并让导航内容成为视觉主体。设计应熟悉、直接、可信，减少当前截图中灰色山脉背景、白字叠深色、厚重装饰与色彩/素材不协调带来的陌生感和生成式模板感。

### 1.2 设计原则

1. **熟悉优先**：遵循成熟网址导航站的常见顺序：品牌与主导航 → 搜索 → 便捷入口 → 常用网站 → 分类目录/实用工具。
2. **内容优先**：用户访问的网站链接是首页核心，不让装饰图片、宣传语或推荐卡片压过目录。
3. **轻量克制**：采用苹果式中性灰阶与单一强调色的秩序感，不仿制 Apple 的产品页面、商标、图标、文案或专有视觉资产。
4. **可扫读**：分类名称、站点名称与操作入口保持清晰层级，避免过多卡片、标签、徽章和重复区块。
5. **保持诚信**：加载失败、目录不可用等系统状态按真实情况表达，不伪装成普通内容，也不隐藏可恢复的错误提示。
6. **不做资讯流**：首页不新增未经明确需求和数据来源支持的天气、新闻、热榜、实时资讯或伪个性化模块。
7. **单一焦点**：首屏只有一个视觉主角（居中的搜索框）；日期、便捷入口、提示条等按「主 → 次 → 弱」排序，不用并列模块平均用力。

### 1.3 本次范围

- 主页桌面端与移动端的视觉方向、信息架构、交互行为、内容状态及验收标准。
- 保留已有搜索、引擎切换、快捷入口、常用网站管理、网站目录、账户/设置、搜索结果与服务提示等能力。
- 网站图标/标识的呈现规则与回退行为。

### 1.4 非目标与护栏

- 不要求更换技术栈、重构导航数据、改变账号/同步/推荐业务逻辑。
- 不新增天气数据源、新闻聚合、热门榜单、广告或营销首屏。
- 不把现有个性化推荐扩展为 AI 推荐；不展示没有真实依据的点击量、热度、天气或动态数据。
- 不要求所有分类、链接都改成相同的独立卡片。
- 不直接使用苹果、hao123 或 360导航的官方商标、专有图标或未经授权的素材。

## 2. 用户与典型任务

### 2.1 主要用户

- 想快速打开搜索引擎、新闻/视频/购物/办公/学习/工具类网站的一般中文互联网用户。
- 习惯通过首页收藏或常用入口访问固定网站的回访用户。
- 使用手机浏览器、屏幕较窄或依赖键盘/辅助技术的用户。

### 2.2 核心任务

1. 进入页面后立即输入关键词，选择搜索引擎并提交搜索。
2. 一眼找到常用网站或常用小工具并打开。
3. 按分类浏览网站，理解当前分类与入口关系。
4. 在需要时添加、移除或置顶常用网站，登录或更改隐私/显示设置。
5. 目录或网络服务出现问题时，知道问题是什么并能尝试恢复。

### 2.3 用户习惯假设

- 搜索框是首屏最常见的起点，应该突出但不需要占据整屏。
- 高频访问入口应在搜索之后、目录之前，减少反复查找。
- 用户更习惯网站文字名称配合熟悉的站点图标；不应要求用户解读抽象插画或装饰性字母标。
- 分类目录适合以紧凑、连续的链接清单呈现；密集网址不宜每项都包装成大卡片。
- 用户会把页面最上方视为品牌/主导航，把搜索区域视为核心操作区，把错误通知视为系统状态；三者在视觉上必须各自清楚。

## 3. 当前体验问题（基于提供截图与现有页面结构）

1. **搜索首屏风格偏离导航站心智**：当前以灰色层叠山脉作为大面积背景，顶部导航、日期与标题使用白字，搜索区显得像活动横幅，而非日常工具入口。
2. **前景和内容区衔接不自然**：背景图形与下面浅灰页面之间形成明显的视觉切换，注意力容易被山形轮廓吸引。
3. **主操作层级不够自然**：导航、日期问候、搜索引擎、搜索框和便捷入口都叠在同一视觉场景上，视线层级不如成熟导航站直观。
4. **素材与品牌识别需要统一**：抽象图形和非真实站点标识容易显得像通用模板。应优先让真实网站名称和可识别图标承担识别任务，避免为每个链接另造风格化插画。
5. **状态通知必须和常规内容分开理解**：目录服务暂时不可用时，提示条是重要运行状态，不应为了视觉统一而将其改成普通卡片或弱化到不可见；新的视觉系统须明确覆盖错误/加载状态。

## 4. 信息架构与页面布局

### 4.1 桌面端首屏顺序（方向 B，基准视觉稿 `previews/preview-b-search-minimal-1440.png`）

页面内容最大宽度 1120px，左右留白 26px；自上而下依次为：

1. **顶部导航栏**（高 52px，白底，底部 1px 细线 #e8e8ed）：左侧品牌标识（22px 蓝色圆角方块 + 「好123」15px/600 + 「轻导航」11px 灰色，以竖线分隔）；中部主导航（轻导航、网址导航、AI工具、我的常用，13px，当前项蓝色加粗并带 2px 蓝色下划线）；右侧「首页设置」（12.5px 灰色 + 滑杆图标）与「用户登录」（12.5px 描边按钮，圆角 8px）。
2. **搜索区**（居中，顶部留白 52px）：日期「10月13日 星期二」为 12px 灰色弱信息，置于引擎行上方；搜索引擎为搜索框**上方的一行小 tab**（百度/必应/Google，13px，选中项加粗并带蓝色下划线，不只靠颜色表达）；搜索框**宽 560px、高 48px、圆角 13px**，白底、1px 细线 #d2d2d7，聚焦时边框变蓝并带 3px 淡蓝焦点环；内部右侧为主按钮「搜索一下」（蓝色 #0071e3、高 36px、圆角 10px、13px/500 白字）；搜索框下方为一行 12.5px 纯文字便捷入口（铁路12306、中国天气网、快递100、百度翻译），不做成芯片或按钮。
3. **服务提示**（内联细条）：与搜索框同宽 560px 居中，中性浅灰底 #f5f5f7、1px 细边、圆角 9px、12.5px 次级文字；左侧小号信息图标，右侧「重试」文字按钮；不遮挡导航与搜索，不用大面积高饱和色。
4. **我的常用**（书签条，非卡片）：区块标题「我的常用」15px/600，右侧「管理」蓝色链接；入口为「20px 圆角 favicon + 13px 名称」的紧凑横排，flex 换行、横向间距 24px，不用灰底方块，不做单字占位；末尾为「+ 添加网站」虚线描边 chip（圆角 9px）。
5. **网站分类**（目录主体，无右侧栏）：区块标题「网站分类」15px/600，右侧「按分类查找网站」12px 灰色链接；下方为分类 tab 行（全部分类/新闻/视频/购物/社交/办公/AI工具/学习/工具，13px，选中项加粗 + 蓝色下划线，底部 1px 细线）；目录为**四列分组网格**（列间距 28px、行间距 24px），每组 = 13px/600 分类标题（带 14px 灰色小图标）+ **两列链接列表**（12px，行高 24px，每项前置 14px favicon）。
6. **日常小帮手**（一行文字，不做侧栏、不做卡片）：置于页脚上方，标签「日常小帮手」12px 灰色 + 一排 12.5px 文字链接（查天气、买车票、查快递、翻译、看地图、转PDF、查汇率、网速测试）。
7. **页脚**：顶部 1px 细线，12px 灰色文字，左侧「关于好123 · 隐私与设置 · 网站投稿 · 帮助中心」，右侧「© 2026 好123」。

顶部导航与搜索区应视觉上可区分，但不必以大幅插画横幅隔开。主内容的排列应让用户自然向下浏览，不以页面高度制造营销式首屏。方向 B **不设右侧边栏**：日常小帮手并入页脚上行，个性化推荐仅在现有推荐数据满足显示条件时以轻量方式出现（见 4.2）。

### 4.2 内容区域

- “我的常用”继续保留独立区块；操作态清楚标出管理、添加、置顶和移除。入口以书签条形式呈现（见 4.1 第 4 条），图标为真实站点 favicon，失败时按 5.4 回退。
- 分类目录采用“分类标题 + 站点链接列表”的连续内容结构，四列分组、组内两列链接。分类入口数量较多时，可通过当前分类筛选减少浏览负担；当前选中类别需有文字和视觉两种状态反馈。
- **不设右侧边栏**。日常小帮手仅保留已有明确目的的工具链接，以页脚上方一行文字呈现；若未来确有需要，可按方向 A 的 208px 窄栏形式扩展，但需单独评审。
- 个性化推荐模块只在现有推荐数据满足显示条件时出现，置于目录之后，标题不得误导为实时 AI 生成内容；若与 AI 工具分类重复，优先保留分类入口。
- 搜索结果、空状态、目录加载和服务错误继续使用各自语义明确的状态表现。
- 不重复呈现同一内容；不用资讯流、广告或推广位填充空白。

### 4.3 截图所示服务提示

当目录服务暂时不可用时：

- 保留清晰可见、非模态的服务提示和“重试”操作，不遮挡品牌导航或搜索主操作。
- 采用中性表面、细描边与易读正文；提示可使用小型状态图标区分，但不要用大面积高饱和色抢占首页视觉焦点。
- 不能仅靠颜色传达故障；错误正文、重试按钮和读屏播报均须明确。
- 重试期间应有可感知的处理中状态，避免重复提交；重试失败后保留原因提示；恢复后移除提示并展示实际目录内容。
- 不得把“目录服务暂时不可用”改成“暂无内容”或伪装成正常目录，以免用户误判数据状态。

## 5. 视觉设计方向

### 5.1 色彩体系（Apple-like 中性风格，不复制品牌）

以中性色建立层次，用单一蓝色作为操作强调。以下色值已按方向 B 的静态视觉稿确定，实现时需在真实设备上做对比度复核（见第 8 节）。

| 语义 | 色值（方向 B 定稿） | 使用规则 |
|---|---|---|
| 页面底色 | `#fbfbfd` | 全页安静背景，避免偏蓝紫或偏绿 |
| 内容表面 | `#ffffff` | 顶栏、搜索框、登录按钮等需要界定边界的表面；不给每个链接套卡片 |
| 主文字 | `#1d1d1f` | 标题、站点名称、主要操作说明 |
| 次级文字 | `#6e6e73` | 描述、辅助说明、页脚 |
| 弱信息文字 | `#86868b` / `#aeaeb2` | 日期、搜索框 placeholder；不用于关键文字 |
| 分隔线 | `#d2d2d7`（边界）/ `#e8e8ed`（区块分隔） | 细线分隔导航、tab 行与页脚，少用重边框 |
| 唯一强调色 | `#0071e3`（hover `#0077ed`） | 当前导航、搜索主按钮、文字链接、分类选中下划线、键盘焦点 |
| 焦点环 | `rgba(0,113,227,.18)` 3px | 搜索框聚焦等需要明确反馈的场景 |
| 浅强调底 | `#eef4fd` | 「重试」等文字按钮的 hover 底，仅小面积使用 |
| 提示条表面 | `#f5f5f7` + `#e8e8ed` 细边 | 目录服务提示等内联状态条 |
| 语义状态色 | 仅按状态必要使用 | 面积小、含文字标签，不与强调蓝混用造成误读 |

- 避免大面积蓝紫渐变、彩色光晕、多层重阴影、青绿色叠加和每个区块不同色相。
- 搜索主按钮与焦点状态使用强调蓝；其他链接默认用主文字色，hover/焦点再明显强调。
- 搜索区不加渐变；用白表面 + 细线界定，不用装饰图片。
- 页面背景、错误提示和内容表面之间靠明度差分层，不依赖阴影制造深度。

### 5.2 字体与排版

- 使用系统中文字体栈（`-apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Segoe UI", sans-serif`），优先保证 Windows、macOS、Android、iOS 上均有稳定回退。
- 方向 B 定稿字号：品牌名 15px/600；导航 13px；区块标题 15px/600；分类标题 13px/600；目录链接 12px；便捷入口/小帮手 12.5px；日期、页脚、辅助说明 12px。不使用小于 12px 的正文。
- 品牌名称与导航层级清楚但不过度加粗；正文、网站链接保持易扫读。
- 日期和辅助说明不应小到难以辨认；重点交互文本优先满足 WCAG AA 对比度。
- 以一致的间距和基线组织内容：区块间距 34px，tab 行与列表间距 20px，避免各模块标题字号、字重、边距各自为政。

### 5.3 形状、边框与阴影

- 圆角分级（方向 B 定稿）：搜索框 13px、主按钮 10px、虚线添加 chip 9px、提示条 9px、登录按钮 8px、favicon 3–5px。不把所有组件做成同一药丸。
- 内容区域仅靠留白、对齐和细分隔线组织，不给目录、常用、工具套卡片边框。
- 阴影只用于确有悬浮层级的弹窗或菜单（含搜索框聚焦时的 3px 淡蓝焦点环），普通内容区无投影。
- Hover 反馈轻微（仅颜色变化）且不改变布局；触屏设备不依赖 hover 才能理解可点击性。

### 5.4 网站图标与图片

- **默认优先级**：网站自有 favicon/站点图标（可稳定获取且授权/使用条件允许）→ 统一的中性文字首字母回退块 → 无图标时使用统一的通用网站符号。
- 回退块规格：圆角 6px、底色 `#e8e8ed`、文字 `#6e6e73`，全站统一，不为每个站点随机配色；不把首字母伪装成官方 Logo。
- 图标尺寸（方向 B 定稿）：常用书签条 20px（圆角 5px）、目录链接 14–15px（圆角 3px）、移动端常用 26px（圆角 7px）。
- 首页首屏不再依赖大幅装饰性山脉图作为主视觉。若未来保留品牌插画，必须弱化、静态、低对比、不妨碍搜索和导航，并经过真实设备视觉评审；本需求不要求制作新图片。
- 不使用来源不明的图片或生成式“假 Logo”；不为装饰而增加外部图片请求。

## 6. 交互与行为规范

### 6.1 顶部导航

- 当前页面/分类必须有明确选中状态，并提供语义状态（例如 `aria-current` 或等价方式）。
- “我的常用”入口应滚动到常用区或进入明确管理状态；操作结束可回到可见内容。
- 设置、登录或账户入口保持可辨认、可点击；登录未就绪时禁用状态要有适当可访问说明。

### 6.2 搜索

- 搜索引擎以搜索框上方的一行小 tab 呈现（百度/必应/Google），保留当前选择与持久化行为；选中项加粗并带蓝色下划线，不只靠颜色表达。
- 搜索框宽 560px（移动端全宽）、高 48px、圆角 13px；输入框有明确 label/辅助技术名称、可理解的 placeholder（「搜索网站或关键词」）、键盘提交方式和搜索按钮。
- Enter 提交与点击搜索按钮行为一致；空输入不发起空搜索。
- 站内搜索结果、无结果状态及外部搜索入口保持现有语义；打开外部网站时保留安全的外链行为。
- 便捷入口为搜索框下方一行纯文字链接，数量保持少而精（当前 4 个：铁路12306、中国天气网、快递100、百度翻译），不塞入未经核实的实时热词或广告。

### 6.3 常用与目录

- 网站入口提供清晰的名称和足够大的触控区域；图标缺失不影响打开网站。
- 管理模式下置顶/移除操作必须有明确名称、结果反馈及可撤销/重新添加路径（沿用现有能力范围）。
- 分类筛选状态可通过键盘操作；筛选后焦点不丢失，列表结果能被读屏用户感知。

### 6.4 加载、错误与空状态

- 加载态应保留稳定布局，不因异步内容到达而大幅跳动；已有种子目录仍可阅读时，不应无故用骨架遮挡。
- 加载动画尊重 `prefers-reduced-motion`；不以持续闪烁制造注意力。
- 目录服务故障提示具备文字、图标/语义与可操作的重试入口；重试失败不清空可用的已有内容。
- 空状态须准确表达“没有匹配结果”或“当前没有常用项”，不可与服务端故障混淆。

## 7. 响应式与触控要求

### 7.1 桌面端（宽屏，≥1120px 内容宽度）

- 顶部导航保持一行；搜索区居中，搜索框固定 560px；目录四列分组网格占满内容宽度。
- 常用入口以书签条横排，随宽度自然换行，不因宽屏而拉得过散；分类链接维持规整列网格。
- 方向 B 无侧栏；窗口继续变宽时，内容区保持 1120px 最大宽度居中，不无限拉伸。

### 7.2 平板与窄桌面（约 768–1119px）

- 目录由四列降为三列，组内链接保持两列；分类 tab 允许横向滚动或换行，但不得被截断到无法辨认。
- 搜索框宽度可随视口收缩（最小不小于 320px），主按钮保持可见。

### 7.3 手机（≤767px，基准视觉稿 `previews/preview-a-mobile-390.png`）

- 顶部品牌、设置/账户入口不得互相覆盖；主导航转为顶栏下方可横向滚动的一行（轻导航/网址导航/AI工具/我的常用），不做折叠菜单、不隐藏入口。
- 搜索框全宽、高 44px，引擎以内嵌小按钮呈现；便捷入口自动换行；软键盘出现时不得遮住提交操作。
- 我的常用改为四列网格（图标在上、名称在下，图标 26px、名称 11.5px 截断显示），「+ 添加」为虚线格；名称过长时省略号截断，不换行撑高网格。
- 目录单列展示，组内链接两列；分类 tab 横向滚动；日常小帮手两列文字列表。
- 可点控件目标建议不小于 44 × 44 CSS px；无法扩展可见图标时，扩大点击热区并确保相邻控件间距。
- 页面支持 200% 字体缩放且无水平滚动；长网站名和错误文案可换行。
- 不新增遮挡页面的固定底栏，除非后续用户测试确认必要。

## 8. 无障碍与可用性要求

- 正文与背景达到 WCAG 2.2 AA 对比度基准：普通文本至少 4.5:1，大文本至少 3:1；焦点指示和必要图形边界至少 3:1。
- 全部主要功能支持键盘访问，Tab 顺序符合视觉阅读顺序；焦点指示清晰可见，不被裁切或被 sticky 区域遮挡。
- 提供跳过导航直达主内容的入口；标题层级语义连续；导航、主内容、辅助栏与页脚使用适当地标。
- 图标按钮有可访问名称；仅装饰的图标对辅助技术隐藏；站点图标失败回退时仍以站点名称作为链接名称。
- 搜索结果更新、重试进度和服务错误通过适当的 live region 或状态语义播报；错误不能只用颜色提示。
- 尊重减少动态效果设置；动画不闪烁，不强制自动播放。
- 不以颜色作为唯一的选中、错误、成功或链接识别依据。

## 10. 验收标准

### 10.1 视觉与信息架构

- 首屏无需滚动即可辨认品牌/主导航、搜索框和便捷入口；搜索框（560px 居中、蓝色主按钮）是首屏主要操作焦点。
- 不再以灰色山脉大图、问候语大标题和白字压深色背景作为主页主要视觉；页面整体以中性色层级和单一强调色建立秩序。
- 页面无圆角白卡容器：常用为书签条、目录为四列链接列表、小帮手为一行文字；三者与服务状态有清楚区分。
- 站点图标使用真实 favicon；无灰底方块 + 单字占位；favicon 失败时回退为统一中性首字母块。
- 无新增未经证实的天气、新闻聚合、热榜或装饰性假 Logo。

### 10.2 行为与内容

- 所有第 9 节既有功能的入口仍能找到并完成原有任务；搜索键盘提交、引擎切换（tab 形式）、常用管理、分类筛选和重试行为正常。
- 目录服务故障时真实提示和重试功能仍可见；故障与空目录、无搜索结果明确区分。
- 图标加载失败有统一回退，站点名称仍可读、可访问。

### 10.3 响应式与可访问性

- 在桌面宽屏、平板、手机窄屏下无文字重叠、操作遮挡或不必要的横向滚动；目录列数按 7.1/7.2 规则降级。
- 手机主要操作热区满足 44 × 44 CSS px 目标；页面放大至 200% 后仍可使用。
- 键盘可完成搜索、导航、分类筛选和弹窗关闭；焦点顺序明确，焦点环不被裁切。
- 正文/控件对比度满足 WCAG AA；屏幕阅读器可辨认导航、搜索、错误和加载状态。
- 系统启用减少动态效果时，无持续动效。

## 11. 评审待确认事项

1. **站点 favicon 策略**：可直接使用站点 favicon 的范围、缓存/代理策略和第三方请求限制需由实现评审确认；产品要求是失败时按 5.4 稳定回退，不锁定具体技术路径。
2. **AI 工具入口与推荐模块**：维持现有导航和目录功能；推荐模块仅在现有推荐条件满足时轻量展示，避免与 AI 工具分类重复堆叠（方向 B 无侧栏，推荐位置需在实现评审中确定，建议置于目录之后）。
3. **深色模式**：方向 B 当前只定义浅色；是否需要深色模式（含山脊/横幅在深色下的处理）需单独确认，确认后可补充预览稿。
4. **日期信息**：当前以 12px 弱信息置于引擎行上方；是否提供隐藏开关（如设置项）待确认。
5. **色值复核**：第 5.1 节色值已定稿，仍需在真实设备上完成对比度测量（正文/次级文字/焦点环/主按钮），不达标项微调后同步更新本文与 `previews/mockup-b-search-minimal.html`。
