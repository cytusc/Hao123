## 1. 反馈与提示 — 首批修复

### 1.1 Toast 分型与正确语义（P0 / S）

现状：`src/main.jsx:932` 把错误消息写入同一个字符串；`:995` 永远渲染 Check；`src/styles.css:1256` 永远使用绿色图标。

建议状态采用 `{ id, msg, kind }`，kind 为 success / error / info；唯一 id 让连续两次相同消息也能重启计时与播报。普通本地操作成功用 Check，错误用 X 或警告图标，容量提示用 Info。批量校准以下调用点：

| 落点 | 拟议类型与文案边界 |
| --- | --- |
| `src/main.jsx:156` | info：最多置顶 9 个网站 |
| `src/main.jsx:166/246/466` | success：置顶、添加、移除已更新；不宣称已完成云端同步 |
| `src/main.jsx:930/932` | clearHistory resolve 后 success；reject 后 error，保留错误原文，无有效消息时使用通用失败文案 |
| `src/main.jsx:943/954` | success：本地状态恢复或导入已更新；同步状态继续使用原机制 |

配色应基于实际背景验证。当前深底 `#263953` 上，`#c0392b` 与 `#a15b25` 的对比度分别只有约 2.15:1、2.25:1，不宜直接作为状态图标色。可候选浅红 `#ffb4a9` / 浅橙 `#ffd19a`，正文保持可读；图标、文案和播报共同区分结果，不只靠颜色。

**同时修复弹窗内反馈可见性。** `src/main.jsx:74` 使用 showModal，清空记录操作位于设置 dialog 内（`:925`），Toast 却位于 dialog 外（`:993`）。原生 dialog 在顶层，外部 Toast 的 z-index 无法越过它，读屏也可能忽略外部惰性内容。建议同一反馈状态根据来源选取一个渲染位置：设置弹窗内就近显示反馈，普通页面操作在页面通知区显示；避免两处重复播报。关闭弹窗不丢失仍需阅读的失败消息。不要仅提高 z-index。

验收：成功、错误、容量提示图标和文案一致；设置弹窗保持打开时，清空成功与失败均可见且可播报；置顶成功遇到异步同步失败时，原 service-notice / 冲突提示仍可使用，未把本地成功误报成同步成功。

### 1.2 长文案与停留时间（P1 / S）

落点：`src/styles.css:1238`、`:1254`，`src/main.jsx:131`。

去掉 nowrap，设置 `white-space:normal`、`max-width:min(420px, calc(100% - 32px))`；文本包裹为可收缩元素，配合 `min-width:0; overflow-wrap:anywhere`，图标保持尺寸。短文居中，多行左对齐更容易阅读。完整错误不依赖 title 或单行省略，移动端与读屏均须获取全文。

短成功消息可保留 2600ms。错误建议保留到下一次操作或用户关闭；较长 info 至少延长阅读时间，有关闭入口时鼠标悬停和键盘聚焦暂停自动隐藏。移动位置考虑底部安全区，不覆盖主要操作。

验收：320px 宽度下，长中文、长网址及无空格错误串均无横向溢出；信息在读完前不会自动消失。

### 1.3 入退场生命周期（P1 / S）

落点：`src/main.jsx:126/131/993`，`src/styles.css:1238`。

使用进入 / 显示 / 退出状态；显示计时结束后先退出，最多 200ms 后卸载。所有计时器在替换通知与组件卸载时清理，旧通知回调不能关闭新通知。减少动态效果时直接切换且正常卸载，不能只等可能不触发的 transitionend。

过渡仅 opacity 与最多 4px 的纵向位移；原有 `translateX(-50%)` 居中保持不变，可将位移放在内层。短消息显示时间不因退场缩短。生命周期只改变视觉，不再次写入播报区。

验收：连续操作、同文案重复、退场期间出现新消息均显示最新结果；开启减少动态效果后无动画、无残留节点。

## 2. 视觉与动效 — 保持连续目录

### 2.1 有选择的 hover 反馈（P1 / S）

落点：`src/styles.css:665/674`（常用入口与标记）、`:819`（目录链接）、`:956`（推荐链接）、`:1350/1358`（频道卡片及链接）。原稿中的 `.channel-link:569` 与 `.ai-site-link:979` 并非对应 CSS 定义。

依据 `DESIGN.md` 的连续目录原则，分类文字链接保留现有下划线与颜色反馈，不给每个网址加投影或整体位移。常用图标可轻抬 1–2px 并增加微弱阴影；频道卡片可整体轻抬，置顶按钮随容器移动，避免仅链接移动造成错位。推荐区默认保留静态排布与文字反馈。

新增抬升效果明确限定在 `@media (hover:hover) and (pointer:fine)`；触屏可能模拟或保留 hover，不能假设无需处理。键盘保留现有 focus-visible 描边；减少动态效果时取消位移，保留非运动反馈。

验收：桌面指针下反馈轻微，触屏无粘滞抬升，键盘可识别目标；不改变静止态目录布局。

### 2.3 动效令牌（P1 / S）

落点：`src/styles.css:3` 与 `:1185`。

建议新增 `--ease:cubic-bezier(.2,.7,.3,1)`、`--dur:.15s`；必要的快速交互使用独立 `--dur-fast:.12s`，退出最长 `.2s`。只过渡明确属性，不使用 transition:all。新增动效无持续循环，统一受第 4.3 节约束。

## 3. 加载与空状态 — 保留即时可用的本机目录

### 3.1 首屏加载策略（P2 / 条件实施）

事实落点：`src/navigation.jsx:41/72/118/127`，展示落点：`src/main.jsx:405/433/531`。

当前本机种子目录在网络请求前可见，目录失败也保留本机精选目录。推荐首期维持这条路径，不新增强制骨架，不用 ready 判断目录是否加载完成；否则会因会话等待而隐藏可用导航。

如果浏览器复核证明某个区域确实无可用数据，再对该区域实施静态占位：只在「尚无可展示数据 + 该区域明确在请求中 + 没有失败」时显示，成功为空时使用空状态，失败保留说明和重试。现有 Context 没有 catalogLoading（`src/navigation.jsx:324`）；若将来需要增加，必须单列为目录展示状态，不复用 ready，不调整同步和登录生命周期。静态灰块复用原网格尺寸，标记 aria-hidden，区域单独提供一次加载说明；默认不加 shimmer。

验收：模拟会话慢、目录慢、目录失败与推荐慢，已有站点始终可点；不会先显示真实内容又用骨架遮住；无无限加载，失败能重试。

### 3.2 分类切换与搜索空状态（低优）

落点：`src/main.jsx:183/251/503/599/640`。

首期不加淡出淡入，也不为切换加延迟：opacity 不能解决长列表高度变化，反而可能产生闪烁。保持即时筛选与明确选中态。搜索无结果沿用现有建议及外部搜索入口，补充结果数量的 polite 播报，不播报整个目录。

## 4. 可访问性 — 与反馈同批落地

### 4.1 稳定的状态播报（P1 / S）

落点：`src/main.jsx:994/407/600`；设置弹窗反馈落点见 1.1。

role=status 已隐含 polite，显式 aria-live 主要用于表达意图；不要把「缺显式属性」直接判为无播报。建议稳定挂载空的 live region，再更新文本，增加 aria-atomic=true，状态图标 aria-hidden。成功及一般提示使用 polite；用户刚触发且失败需立即处理的错误使用 role=alert / assertive，避免所有普通通知抢占播报。

页面与原生 dialog 内按当前反馈来源选择播报容器；避免同一消息双播报，不把焦点移到通知，入退场不重复读消息。实际效果需 NVDA / VoiceOver 复核。

### 4.2 Skip-link（P1 / S）

落点：`src/main.jsx:255/405`；`src/styles.css:45` 附近新增独立样式。

在 App 中 SearchStage 之前添加首个可聚焦链接「跳到主内容」，指向 main 新增的 `id=main-content`，main 设置 tabIndex=-1。平时视觉隐藏，focus 时清晰显现并位于搜索背景上方。目标须进入焦点，后续 Tab 从主内容继续；仅滚动而焦点留在头部不算完成。

验收：Tab 第一项为跳转链接，Enter 后焦点进入 main，下一 Tab 进入主内容操作；可见焦点未被遮挡。

### 4.3 减少动态效果（P1 / S）

落点：`src/styles.css:403/1854`；`src/SearchStage.jsx:19/57`；`src/main.jsx:189/303`。

扩展现有 reduce 规则覆盖新增 CSS animation；保留 transition:none 与 scroll-behavior:auto。新增抬升、通知位移都在 reduce 下停止，信息仍完整呈现。

两处 JS 明确调用 scrollIntoView({behavior:"smooth"})，不应只依赖 CSS：调用时根据 matchMedia 选择 auto / smooth。已有横幅监听媒体查询变化且可归零，继续保持；本轮不重写横幅视差。系统减少动态效果即为关闭路径，不为此增加账号设置字段。

「≤200ms」约束新增交互动效；既有视差属于独立连续输入响应，本轮不把其误计为已符合固定时长，也不新增持续 shimmer。

## 5. 信息架构与冗余

### 5.1 AI 角标去永久化（P0 / S）

落点：`src/main.jsx:289/296`；`src/styles.css:154/290`。

沿用时间盒为首选，但明确语义：按固定「入口版本上线日 + 14 天」判断，并在本机首次点击 AI 导航后提前隐藏；不能每次清理存储都重新开始十四天，也不增加访问次数追踪。用独立带版本的 localStorage 已读键，读写异常不影响分类切换；存储不可用时仍受固定到期日约束。该状态只在本机，不写入账号偏好或度量事件。

若此入口没有明确的新版本上线日，建议直接移除角标，避免虚构新鲜度。可关闭方案为只保存一次已读状态；具体采用哪个分支在实现时按上线日期确定。

验收：到期或已点击后隐藏；刷新不重新出现；localStorage 不可用时主导航照常工作，角标不会无限续期。

### 5.2 搜索便捷入口动态化（P2 / S）

落点：`src/main.jsx:136/152/386`。

只复用现有数据，不新增推荐请求或画像字段。登录用户依次取「手动 pinned → 开启个性化时的 recommendation.common → 默认四项」，解析有效站点、排除 hidden、按 id 去重后取四个；自定义网站可使用 sites 解析。关闭个性化时仍可展示手动置顶，但不使用行为推荐；访客保持默认四项。

默认项仅保留当前有效目录里的站点，避免靠已下架的 URL 补齐。继续复用 link，沿用 record 的个性化门禁。便捷入口是直达网站，不改成提交站内搜索。

验收：置顶可出现、隐藏项不出现、重复推荐只出现一次；关闭个性化不显示行为建议；游客看到有效默认项，无额外网络请求。

### 5.3 AI 双入口统一（P2 / S）

落点：`src/main.jsx:289/699/728`。

建议保留顶部「AI 工具」分类入口，去掉侧栏固定三站及「发现更多」重复区；保留已有的「猜你想用」条件区，不新建第二个推荐列表。游客、关闭个性化或没有推荐时不补行为推荐；日常工具仍可用。

移动端顶部 AI 按钮仍需可见、可点；分类目录保留 AI 分类。删除侧栏块后回归 `src/styles.css:1459` 的双栏 sidebar 排布，检查剩余内容流向。此次 IA 调整允许侧栏减少高度，不借机改造首页布局。

## 6. 响应式收尾

落点：`src/styles.css:1044/1066/730/1171/1763`，`src/main.jsx:71/425/581/925`。

1. **弹窗滚动**：保留已有 width、padding、border-radius、max-height:85dvh；明确 overflow-y:auto，验证 overscroll、横屏和软键盘。showModal 不会使 iOS dialog 必然全屏，不把未复核的浏览器表现当成规范事实。
2. **关键热区**：移动粗指针目标至少 44×44 CSS px，40px 仍低于本方案标准。除 30px icon-button，还要检查 24×22 的编辑按钮、39×23 的开关，以及关闭 / 搜索 / 管理按钮。可扩大按钮盒、保持视觉图标尺寸；预留间距，防止扩张后目标重叠。
3. **安全区与可达性**：长设置弹窗、添加网站表单的关闭和提交可滚动到达；底部通知考虑 safe-area-inset-bottom，键盘打开后不遮盖输入或提交。

验收尺寸：320 / 375 / 390 / 480px；横屏矮视口；200% 缩放；桌面 1280 / 1440px。无横向滚动、误触或不可达操作。iOS 主屏引导与底部导航沿用关联 P1-1 排期，不为了本轮打磨引入新导航体系或 PWA。

## 7. 首屏与性能

### 7.1 字体依赖（P2 / S，先测后改）

落点：`src/styles.css:1/4`，`index.html:3`。

@import 增加字体样式发现的依赖链，display=swap 能减少字体不可见阶段，但不能消除该依赖。当前字体栈优先系统苹方，影响随平台而异，先测正常网络、慢网及字体域不可达三种情况。

候选方案：将外部字体改为可选增强；在 index.html 添加 Google Fonts 与 gstatic 的 preconnect（后者 crossorigin），采用不阻塞屏幕样式的字体 CSS 加载方式，保留 display=swap 与系统 fallback。若使用 media=print 切回 all，采用符合现有 CSP 的加载处理；仅移动为普通 stylesheet link 不能声称已异步。也可直接使用系统字体，作为减少外部请求的独立选择。

不添加首屏等待字体的 JS；不预加载全部中文字体文件。验收用真实网络瀑布、FCP/LCP/CLS 与文字截图，不提前承诺 LCP 提升，也不只观察 FOIT。

### 7.2 非关键区域（P3 / 暂不实施）

## 10. 验收总原则与后续检查

- **范围门禁**：方案阶段只交付此文档。实施不改变 `src/navigation.jsx:136` persist、`:60` prefsVersionRef、`:220` resolveSyncConflict、record 门禁或同步队列；登录账号组件仅作回归，不改业务行为。
- **静态布局**：颜色、焦点、hover 动效不改默认目录密度；热区、长文本、skip-link 与 IA 去重允许各自所需的局部变更，逐项核验桌面回归，避免作出「所有静止态完全不变」的不实承诺。

- **网络场景**：目录慢 / 失败、会话慢、推荐慢、字体慢 / 不可达分别验证，不能用一次失败覆盖所有状态。
- **输入与无障碍**：鼠标、粗指针、纯键盘、VoiceOver / NVDA、减少动态效果运行中切换、200% 缩放均验证；通过静态 AA 抽查不等于全站无障碍验收通过。
- **后续工程验证**：纯前端实现后运行 `npm run build`（实际为 vite build）与 `git diff --check`，再做浏览器场景回归。本轮文档核对无需 go build，也不声称完成了尚未实现的浏览器验收。

不新增营销、资讯、逐次访问追踪或画像字段；新增动效短于或等于 200ms，可随系统偏好关闭。每批交付须记录实际改动、验证结果和未验证的平台。
